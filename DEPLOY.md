# Deploying REBIRTH for free

This puts REBIRTH online at a free `…vercel.app` address you can share on your resume.
The code side is already prepared; what's left is creating free accounts and clicking through, which takes about 15 minutes.

| Part | Service | Free-tier limits worth knowing |
|---|---|---|
| Database | [Neon](https://neon.tech) | ~0.5 GB storage, plenty for REBIRTH |
| API (FastAPI) | [Render](https://render.com) | Sleeps after ~15 idle minutes; the first visit then takes 30–60 s (the site shows a "Waking up REBIRTH…" note). 512 MB memory, so AI photo recognition is off online |
| Website (Next.js) | [Vercel](https://vercel.com) | Hobby plan: for personal, non-commercial projects |
| Photos (optional) | [Cloudinary](https://cloudinary.com) | Without it, uploaded photos disappear whenever the free API restarts |

> Free-tier rules change from time to time. Glance at each pricing page when you sign up. None of the steps below need a credit card at the time of writing.

---

## 1. Database: Neon (≈3 min)

1. Go to **neon.tech** and sign up **with your GitHub account**.
2. Create a project: name `rebirth`, Postgres **16**, region **AWS Asia Pacific (Singapore)** (closest to India).
3. On the project dashboard, open **Connect** and copy the **connection string**. It looks like
   `postgresql://user:password@ep-xxxx.ap-southeast-1.aws.neon.tech/neondb?sslmode=require`.
   Keep it private: it's your database password. You'll paste it into Render in the next step.

## 2. API: Render (≈7 min, most of it waiting for the build)

1. Go to **render.com** and sign up **with your GitHub account**. Allow it to see the `Rebirth` repository.
2. Click **New → Blueprint** and pick the `Rebirth` repository. Render reads `render.yaml` and proposes a free web service called **rebirth-api**.
3. It asks for the values marked "sync: false":
   - **DATABASE_URL**: paste the Neon connection string.
   - **ADMIN_PASSWORD** (optional): a private password if you want to use `admin@rebirth.test` on the live site. Leave it empty and the live site has no admin login.
   - **CLOUDINARY_URL** (optional): leave empty for now, see step 4.
4. Click **Apply**. The first build installs everything (5–8 minutes). On its first start the API creates the tables and loads the demo data (~10 seconds).
5. When it shows **Live**, open `https://rebirth-api.onrender.com/api/health` (your exact address is at the top of the service page). You should see `{"status":"ok", …}`.

`JWT_SECRET` is generated by Render automatically. Never put it in the code.

## 3. Website: Vercel (≈3 min)

1. Go to **vercel.com** and sign up **with your GitHub account**.
2. **Add New → Project**, import the `Rebirth` repository.
3. Before deploying, set:
   - **Root Directory**: `frontend`
   - **Environment Variable**: `API_URL` = your Render address, e.g. `https://rebirth-api.onrender.com` (no trailing slash)
4. Click **Deploy**. After about 2 minutes you get your public link, e.g. `https://rebirth-xxxx.vercel.app`.

The website forwards `/api/*` and `/media/*` to Render, so sign-in cookies stay on your Vercel address and work in every browser.

## 4. Photos that survive restarts: Cloudinary (optional, ≈2 min)

1. Sign up at **cloudinary.com** (free plan).
2. On the dashboard, copy the **API environment variable**: `cloudinary://API_KEY:API_SECRET@CLOUD_NAME`.
3. In Render → **rebirth-api → Environment**, set `CLOUDINARY_URL` to that value and save. Render redeploys by itself.

## 5. Check it

- Open your Vercel link. If the API was asleep you'll see Chhotu's "Waking up REBIRTH…" note for up to a minute.
- Sign in with a demo account, e.g. `fatima@rebirth.test` / `rebirth-demo` (all demo accounts are listed in the README).
- Try Explore, the Map, Impact, Forecasts and the Leaderboard. Photo upload works; the AI suggestions are off online (they work when you run REBIRTH on your computer).

Then send me the link and I'll add it to the top of the README.

## Updating the live site

Every `git push` to `main`:
- runs the tests on GitHub (the **CI** badge in the README),
- redeploys the website on Vercel automatically,
- redeploys the API on Render automatically **only if Render is connected to GitHub**. If you created the Blueprint from the public repository URL (as the live demo was), open **rebirth-api → Manual Deploy → Deploy latest commit** after pushing, or connect GitHub under the service's Settings to make it automatic.

## Troubleshooting

| What you see | What to do |
|---|---|
| Render build fails on `pip install` | Check that `PYTHON_VERSION` is `3.12.8` in the service's Environment tab, then **Manual Deploy → Clear build cache & deploy**. |
| Render logs say `Set JWT_SECRET…` or `Set COOKIE_SECURE…` | An environment value is missing; compare with `render.yaml`. |
| Website loads but every page says it can't reach REBIRTH | `API_URL` on Vercel is wrong or has a trailing slash. Fix it, then **Redeploy**. |
| Signing in does nothing | Make sure you're on the Vercel address (not the Render one). Cookies are set for the site you're on. |
| Data looks empty | The seed only runs when the database is empty. In Neon you can reset the database and restart the Render service to seed again. |
